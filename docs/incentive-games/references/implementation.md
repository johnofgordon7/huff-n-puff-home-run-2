# Implementation recipe

1. Inspect the host stack, current shell and assets. Prefer one reusable GameShell, GameStatusBar, BalancePanel, UtilityControls, BetController, StakePicker and ResultFooter over per-screen duplicated markup. Map these conceptual names to existing project conventions.
2. Copy/import the shared tokens from the bundle. Keep per-game art out of the shell. The bundled SVGs are original Figma exports. Play includes its background and stroke; turbo/autoplay exports are glyphs that need the standard circular container. Stake background includes its original outline. Info/menu button exports are also bundled with their circular backgrounds. Source additional state/variant glyphs from existing matching assets or exact Figma nodes in source-map.md.
3. At document level use margin:0, full width/height and overflow:hidden. Use a viewport-height shell (100dvh with a supported fallback) for standalone games; use 100% of the established host container for embedded games. Do not disable zoom or use touch-action:none across the app.
4. Use grid rows for top/status region, minmax(0,1fr) game region and footer; set min-width:0/min-height:0 on flexible children. Position the game HUD and controller within the game region with padding reserved for important game content. Account for env(safe-area-inset-*) once, at the correct container.
5. Centre the play button relative to the game viewport. A controller with left / play / right columns can use equal flexible outer columns and an explicit central width. Do not use justify-content:space-between on unequal control groups as the only centring mechanism. At desktop width keep the control cluster compact and centred rather than stretching controls to the screen edges.
6. Implement compact sizing when the available container width is too small for the regular controller. Preserve 70px primary and at least 44px standard secondary touch targets. Use compact capability variants rather than shrinking everything with transform:scale(). The bundled 320×568 reference includes operator framing; measure the actual available game region.
7. Make the stake popup scroll internally with overflow-y:auto, overscroll-behavior:contain and a bounded max-height derived from available space above/below the trigger. Keep three columns without pagination. Scroll the selected amount into view. Keep the page locked with the popup open and closed.
8. Connect callbacks to host game state, not a parallel wallet/game engine. Expose theme, currency/locale, stake options, balance, last win, game phase and supported features as configuration/props. Hide unsupported controls while keeping the main action centred. Sound settings belong in the menu unless the selected source variant explicitly locates them elsewhere.
9. Test the implementation using acceptance.md. Check current game behaviour after a migration. Keep a project-local record of version and intentional deviations.

The package supplies rules, measurements, visual references, tokens and core vector assets. It does not contain a complete framework-specific UI library. Reuse the implementation in the active project and consolidate new shell code into reusable host components. Do not invent an installed npm package or a source-code mapping.
